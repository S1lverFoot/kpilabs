# ADR 001: Використання UUID та збереження історичної ціни



**Статус:** Прийнято



**Контекст:**

Нам потрібно було визначити тип первинних ключів для всіх сутностей та вирішити проблему можливої зміни ціни товару після оформлення замовлення.



**Рішення:**

1. Використовувати `UUID` для всіх `*ID` полів замість `Auto-increment Integer`.

2. Дублювати атрибут `Price` із сутності `Product` у сутність `Order_Item` під назвою `UnitPrice`.



**Наслідки:**

- `UUID` ускладнює читабельність ключів для людини, але гарантує унікальність при розподілених системах.

- Наявність `UnitPrice` порушує базову інтуїцію про уникнення дублювання, але є бізнес-вимогою для фіксації суми замовлення на момент його створення.
