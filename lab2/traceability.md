# Матриця трасування (Traceability Matrix)

Ця таблиця пов'язує системні вимоги (EARS / User Stories) із сценаріями використання (Use Cases) за схемою багато-до-багатьох.

| Вимога ID | Опис вимоги | Пов'язані Use Cases (UC) | Статус покриття |
| :--- | :--- | :--- | :--- |
| **US-1 / EARS-1** | Перегляд каталогу товарів та збереження ID | UC-1 (Перегляд каталогу), UC-5 (Знижка) | Покрито (1:N) |
| **US-2 / EARS-2** | Формування замовлення та кошика | UC-2 (Оформлення), UC-4 (Авторизація) | Покрито (N:M) |
| **US-3 / EARS-3** | Інтеграція з платіжним шлюзом | UC-3 (Оплата), UC-6 (Помилка) | Покрито (N:M) |
| **REQ-4** | Автоматичне резервування складу на 15 хв при створенні замовлення | *Відсутній* | **Непокрита вимога** |

## Пояснення непокритих вимог:
* **REQ-4 (Резервування складу):** Ця вимога навмисно залишена непокритою в поточній версії діаграми Use Case.
*  У рамках поточного спринту та першої ітерації архітектури ми фокусуємося лише на базовому оформленні та оплаті замовлення.
*   Управління складськими залишками в реальному часі та таймери резервування винесені за межі поточного обсягу (Out of Scope) і будуть реалізовані в наступних версіях системи.
